# 0003: AWS アカウントで環境（dev / prod）を分離する

- 日付：2026-11-19
- ステータス：提案

## 背景

本番と開発で複数の環境を持ちたい。環境を分ける方法として、同じアカウント内でリソース名を分けるか、AWS アカウント自体を分けるかを決める必要がある。
個人〜少人数の開発なので、運用の手間も小さく抑えたい。

## 選択肢

1. **単一アカウント + リソース名のプレフィックスで分離**
   - メリット：構成がシンプルで、すぐに始められる。
   - デメリット：IAM の権限ミスや Terraform の誤操作が prod に波及しやすい。コストを環境別に把握しにくい。Cognito や AppSync のサービスクォータを環境間で共有してしまう。
2. **AWS Organizations で環境ごとにアカウントを分離**
   - メリット：影響範囲（ブラスト半径）が環境で切れる。コストを環境別に見られる。IAM 設計が単純になる（アカウント単位で権限を分ける）。
   - デメリット：初期設定（Organizations・IAM Identity Center）に手間がかかる。アカウントをまたぐ操作には SSO が必要になる。

## 決定

**AWS Organizations で、管理アカウント・dev・prod の 3 アカウントに分離する。**

| アカウント | 役割 |
|------------|------|
| 管理 | Organizations、IAM Identity Center（SSO）、組織の CloudTrail、AWS Budgets。ワークロードは置かない |
| dev | 開発・検証用。main ブランチの内容を自動デプロイする |
| prod | 本番。タグを打ったときに承認を経てデプロイする。WAF・PITR・削除保護を有効にする |

- stg は当面作らない。必要になったら同じ Terraform モジュールでアカウントを追加する。
- リージョンは ap-northeast-1（東京）。
- 開発者は IAM Identity Center でログインし、IAM ユーザーは作らない。
- 各アカウントで Budgets のアラートを設定する。

## 影響

- Terraform を環境ごとのディレクトリ（`envs/dev`, `envs/prod`）と共通モジュールに分けて構成する。state は各アカウントの S3 に置く（ネイティブロック `use_lockfile`）。
- CI からのデプロイには、アカウントごとに OIDC 用のロールが必要（→ [0004](0004-cicd-github-actions.md)）。
- アカウントを増やしても基本料金はかからないが、CloudTrail や Config などをアカウントごとに有効にすると費用がかかる点に注意する。
